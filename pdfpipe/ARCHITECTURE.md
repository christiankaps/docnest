# PDF Pipe architecture

PDF Pipe has one explicit journey: import → automatic OCR and analysis → preview and user-composed filename → user-directed export or discard. The SwiftUI app and share extension embed the same `OneFlowWorkbenchView` and use `OneFlowSessionModel`. There is no pipeline interpreter, template parser, unattended default, or legacy settings reader. The old `pipelines.v1` preference is ignored; old data did not require migration.

## Ownership

- `OneFlowHomeView` handles native Files import, Open In delivery, word-rating settings, and the build-date display. `ShareViewController` receives one supported item provider and presents the same workbench.
- `OneFlowSessionModel` owns phase, cancellation, temporary-session lifetime, analysis, filename choices, export copies, and completion. OCR reports completed pages as a bounded progress fraction; copying is indeterminate and the last portion of the bar is reserved for finalization. The processing card is centered in both app and extension. It keeps the working PDF available after an OCR or export failure. App and extension callbacks clean up after successful handoff or discard.
- `DocumentEngine` stages and validates input, converts JPEG/PNG to PDF, and describes the resulting copy. It delegates recognition to `AutomaticOCR` and creates a newly named temporary copy only when the user requests export.
- `AutomaticOCR` renders each page and runs Vision even when embedded text exists. Its raster transform explicitly scales the PDF page into the allocated bitmap; the Core Graphics fit transform alone can leave a small page centered at its original point size, degrading recognition. The same transform maps existing text bounds for mixed-page overlap checks. It configures only the supported phone language and English, in that order, with automatic language detection enabled. `PDFPageOrigin` scans PDF drawing operators and classifies a page as replaceable old OCR only when a placed image covers at least 85% of the page and all text-show operations are invisible. The same conservative evidence describes imported pages as digital, scanned, mixed, or unclear; `DocumentOrigin` summarizes them for the visible source-origin card. The classification is retained from the imported file, not recalculated on the OCR result. Ambiguous pages retain embedded text. Clear scan pages are rendered at up to nine million pixels, JPEG encoded, and given only Apple OCR's invisible Core Text layer; drawing their original PDF operators would retain the old OCR. Native and mixed pages retain their PDF drawing operators and gain only missing image lines. Annotations, forms, and signature structures prevent rewriting the document. Simulator tests cover mixed text, scan replacement, native text, and source bytes. PDFKit's `page.string` can omit an invisible layer even though its selection API and external PDF text extraction include it.
- OCR builds one per-page analysis source: embedded text for native pages, Apple OCR for clear scan pages, and embedded plus missing OCR lines on mixed pages. The naming screen consumes that analysis directly. Document text remains in the temporary session's memory only.
- `DocumentAnalyzer` ranks dates and words separately for embedded and recognized text. It keeps per-word visual size, position, source, and OCR confidence in memory for the active session. Native PDF size comes from PDFKit character bounds; OCR size uses Vision line bounds. A decaying page-position bonus strongly favors early pages; capped frequency and relative-size bonuses, a bounded bonus for short lines near the start of a document, and font-trait bonuses where PDFKit reports them refine significance. Repeated lines count once across pages, and footers are deboosted. PDFKit can substitute regular fonts in attributed text, so bold/italic are not guaranteed even for visibly styled PDFs. `WordFeedback` loads explicit thumbs-up/down preferences from App Group UserDefaults, applies a capped additive score before choosing 30 suggestions, and never creates a suggestion absent from the document. The model freezes that ranking when processing finishes; later votes update only the chip indicator until a new import. `FilenameComposer` stores ordered parts and the separator captured when each part was appended. Direct editing forms a custom part and supports one-step Undo. `SafeFilename` validates the exact string shown before export.

## File safety and concurrency

An import is copied into a protected, backup-excluded App Group `Library/Caches/Sessions/<UUID>` directory. App-owned Open In deliveries are moved there before asynchronous work; external originals are opened only for reading. Advisory locks protect active sessions from abandoned-session cleanup by another process. Import copying streams data and checks cancellation. The engine is an actor; UI/session state is main-actor owned. Session files are removed after export or discard, and abandoned unlocked sessions are reclaimed on later launch/import. Only explicit word ratings persist in App Group preferences; no PDF, recognized text, unrated suggestions, or filename history is persisted by PDF Pipe.

The share extension completes its host request only after an explicit user export and session cleanup; discard cancels the request. Successful handoff does not guarantee that another app or cloud provider permanently retained the file.

## Project and verification

`project.yml` and `make generate` own target membership, plists, entitlements, and signing settings. Both targets support iPhone on iOS 26+. `make verify` runs the short simulator suite, Release static analysis, and an optimized unsigned device build. A signed Release was installed and launched on an iPhone 14 Pro; provider and real-document behavior still need targeted device qualification. The app build phase stamps a UTC build time into its bundle, displayed locally on Home.
